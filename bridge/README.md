# IMA 本地摆渡工具

该工具运行在同时能够访问 IMA 和内网基线库的本地电脑上。它读取 IMA 元数据和文档内容：元数据写入 PostgreSQL，文档流从本地电脑上传到内网基线库的 MongoDB GridFS。IMA Client ID、API Key 不会进入前端或部署到内网服务器。

## 准备

1. 安装 Node.js 18 或更高版本。
2. 将 `.env.example` 复制为 `.env`，填写 IMA OpenAPI、知识库、分享 ID、内网应用地址和平台管理员账号。
3. 确认本地电脑可以访问 IMA OpenAPI 和 `${PORTAL_BASE_URL}/actuator/health`。

`.env` 含凭据，不要提交、发送或放入 Tomcat。工具没有第三方 npm 依赖，不需要执行安装。

## 执行

先只读取元数据并核对统计，不下载文件、不写入基线库：

```powershell
cd bridge
npm run dry-run
```

确认九个环节数量正确后执行正式同步：

```powershell
npm run sync
```

每次正式同步会先分页发现九个环节，然后逐个环节、逐页读取。每个 IMA 文档先在本地获取下载地址，流式上传到内网 GridFS；获得 `fileId` 后，资产元数据按 50 条一批写入 PostgreSQL。不会把单个目录、单个文件或全部知识库一次性放入内存。只有所有环节和批次都成功且完成接口调用成功，后端才会停用本次已经从 IMA 移除的旧条目；网络中断或程序异常不会停用既有数据。重复执行时以 IMA `media_id` 更新同一条资产，GridFS 按 SHA-256 复用相同文件，不会重复存储。

工具默认将 IMA 请求间隔控制为 1.5 秒，每处理完一个环节暂停 2 秒。IMA 即使以 HTTP 200 返回“请求频率超限”，工具也会按 10、20、40 秒逐级退避，最长等待 60 秒，最多重试 10 次。终端会分别显示“IMA 分批读取”和“基线库分批写入”进度。

限流仍较严格时，可在 `.env` 中调大 `IMA_REQUEST_INTERVAL_MS`，例如改为 `3000`；不建议通过增大 `IMA_PAGE_SIZE` 或并发请求规避 IMA 限流。

单个文件默认最大 300 MB，与 Tomcat 和平台上传限制一致。可通过 `IMA_FILE_RETRIES` 控制下载/上传重试次数；文件超过 `IMA_MAX_FILE_SIZE_MB` 时同步会停止并保留现有基线库数据，避免产生不完整快照。

默认要求识别到 0-8 九个环节目录，且元数据总数不能为 0，否则在写入前终止。这可以防止目录改名或权限异常被误判为“IMA 已删除”。如果当前知识库只维护部分环节，可以在 `.env` 中明确缩小 `BRIDGE_REQUIRED_STAGES`，例如 `0,1,2`。

同步后，“在线预览”和“下载”均直接读取内网基线库的 GridFS 文件，不依赖 IMA。资产标题和“在 IMA 客户端中定位”按钮使用 `shareId + mediaId` 打开 IMA 网页端的自动定位链接；已安装 IMA 桌面客户端且浏览器允许外部协议时，IMA 会被唤醒并定位到该文件。文件尚未入库时仅提供 IMA 定位入口。
