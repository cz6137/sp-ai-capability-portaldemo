# 会议纪要生成器接入说明

## 接入结论

平台接入的是实物工具的核心处理链路，不直接运行或分发原始 BAT，也不把供应商密钥放进浏览器。原工具中“选择录音、补充背景、转写、生成纪要、人工修改、导出”的主流程保留；本地 PowerShell 代理改为平台后端接口。

当前实现采用首版可部署架构：

```text
浏览器选择录音
  -> 平台后端临时文件
  -> 讯飞录音文件转写
  -> 平台配置的 OpenAI 兼容模型
  -> 浏览器人工确认与导出
```

未完成服务配置时，页面只显示“真实处理服务尚未配置”，不会上传文件、播放模拟进度或生成固定结果。

## 配置项

以下值应由部署环境的密钥管理或环境变量注入，不要写入前端、JSON 清单或代码仓库：

| 环境变量 | 用途 | 必填 |
| --- | --- | --- |
| `PORTAL_MEETING_MINUTES_ENABLED` | 是否开放真实处理，生产启用时设为 `true` | 是 |
| `PORTAL_XFYUN_APP_ID` | 讯飞应用 ID | 是 |
| `PORTAL_XFYUN_SECRET_KEY` | 讯飞录音文件转写 SecretKey | 是 |
| `PORTAL_AI_BASE_URL` | OpenAI 兼容接口地址，不含 `/chat/completions` | 是 |
| `PORTAL_AI_KEY` | 模型服务密钥 | 是 |
| `PORTAL_AI_MODEL` | 模型名称 | 否，默认 `deepseek-flash` |
| `PORTAL_MEETING_MINUTES_MAX_FILE_SIZE_MB` | 单个录音上限 | 否，默认 200，最大 500 |

平台还需要保证 Spring Multipart 上限不小于工具文件上限。当前默认值为单文件 300 MB、单请求 305 MB。

## 平台接口

下列接口路径均按应用内部路径书写。前端通过统一 HTTP 客户端访问时使用 `/api/v1/...`；部署到 Tomcat 后，对外完整路径需要加上后端应用上下文，即 `/sp-ai-portal/api/v1/...`。反向代理或网关如重写上下文，应以部署环境配置为准。

### 查询服务状态

`GET /api/v1/tools/meeting-minutes/capabilities`

返回是否可用、支持格式、文件上限、外部服务、处理位置与留存说明。前端必须先读取这个接口，再决定是否允许提交。

### 创建真实处理任务

`POST /api/v1/tools/meeting-minutes/jobs`

请求类型为 `multipart/form-data`：

- `file`：真实录音文件，必填；
- `subject`：会议主题；
- `attendees`：参会人员；
- `background`：项目背景；
- `template`：纪要模板；
- `durationSeconds`：浏览器读取到的录音时长。

### 查询任务

`GET /api/v1/tools/meeting-minutes/jobs/{id}`

任务状态为 `QUEUED`、`TRANSCRIBING`、`GENERATING`、`COMPLETED` 或 `FAILED`。任务只允许创建者查看。

## 前端渲染与导出说明

会议纪要属于 `server-job` 运行型工具：录音提交后由后端异步处理，前端持续轮询任务状态，再允许用户修改和确认结果。因此它仍使用 `runtime.renderer: custom`，作为统一工具渲染体系中的明确例外，而不是每接入一个工具都重新开发页面的范例。

自定义页面只承载异步任务、结构化结果编辑等特有流程；文件拖拽、分步面板和文档预览继续复用平台公共组件（`ToolFileDropzone`、`ToolPanel`、`ToolDocumentPreview`），交互措辞、状态反馈和结果确认方式应与其他工具保持一致。

当前三个导出入口的实际实现如下，页面和验收时不应将其描述为尚未具备的格式能力：

| 页面入口 | 当前实际产物 | 使用说明 |
| --- | --- | --- |
| 下载 Word | HTML 内容封装为 Word 兼容的 `.doc` 文件 | 可由桌面 Word 打开，但不是标准 `.docx`；复杂版式需人工复核 |
| 下载 Markdown | UTF-8 编码的真实 `.md` 文件 | 可继续编辑、纳入版本管理或交给其他工具处理 |
| 打印 / 另存 PDF | 打开浏览器打印窗口 | 由用户在浏览器中选择“另存为 PDF”，当前不由后端直接生成 PDF 文件 |

## 数据与安全边界

- 录音会传至平台后端和已配置的讯飞转写服务；转写文本会传至已配置的模型服务。页面应在上传前明确告知用户。
- 后端临时录音在任务完成或失败后立即删除。
- 当前任务和结果只保存在后端进程内，保留两小时；服务重启后任务不可恢复。
- 模型提示词把转写内容视为不可信数据，禁止执行录音中出现的指令，并要求不得补造人物、时间、数字、结论或待办。
- 生成结果必须由用户人工确认后才能作为正式会议纪要使用。

## 上线检查

1. 在测试环境配置讯飞和模型服务，确认服务状态接口返回 `READY`。
2. 使用不含敏感业务信息的录音完成一次端到端测试，核对转写、摘要、决策和行动项。
3. 验证失败任务、超大文件、错误格式、无权限查询和外部服务超时。
4. 与安全及法务确认外部服务的数据处理地域、账号权限、日志和合同边界。
5. 正式开放前补充任务持久化、审计记录、并发队列监控和可配置留存策略。

## 与原实物的差异

| 原实物 | 平台接入 |
| --- | --- |
| BAT 解包并启动本地 PowerShell 代理 | Spring Boot 后端统一提供接口 |
| 密钥可能随 HTML/本地配置分发 | 密钥仅由部署环境注入后端 |
| 浏览器本地历史记录 | 首版为后端进程内两小时任务记录 |
| 本机打开独立 HTML | 统一纳入工具页面模板、登录与权限体系 |
| 固定本地端口和宽松 CORS | 使用平台同源 API 与现有鉴权 |

首版完成了“真实可接入”的最小闭环，但任务持久化、审计、配额和供应商切换仍属于生产化工作，不应在页面上伪装为已经具备。
